## Refactor money-manager-mcp onto FastMCP

### Goal
Replace the hand-wired low-level `@modelcontextprotocol/sdk` `Server` + `setRequestHandler` plumbing with the `fastmcp` TypeScript framework, eliminating the triple-definition of every tool and the double-validation. Result: clean, minimal, single-source-of-truth tool registration.

### Confirmed decisions
- **Backup tools** (`backup_download`, `backup_restore`): **fully removed** (handlers, schemas, types, docs references).
- **Errors**: **native MCP errors** — handlers throw existing `McpError` subclasses; FastMCP surfaces them as `isError` results. The `{ success:false, error:{...} }` JSON envelope is dropped. Success results keep their current JSON-stringified text format.

---

### Key insight: triple-definition → single definition
Today each tool is defined three times (JSON Schema in `TOOL_DEFINITIONS`, Zod in `ToolSchemas`, handler in `toolHandlers`) and validated twice. With FastMCP, each tool is registered **once** — a Zod schema auto-generates the JSON Schema advertised to clients, validation happens once, and dispatch is automatic.

---

### File-by-file changes

**1. `package.json`**
- Replace dependency `@modelcontextprotocol/sdk` → `fastmcp` (latest).
- Bump version `1.0.0` → `2.0.0` (major refactor; breaking error wire-format + removed tools).
- No other script/config changes.

**2. `src/index.ts` — full rewrite (~670 → ~100 lines)**
Replace the `MoneyManagerMcpServer` class with a flat `main()`:
- `new FastMCP({ name: "money-manager-mcp", version })`.
- Parse `--baseUrl` CLI arg (kept), `loadConfig()`, create `httpClient` (unchanged).
- A small `register({ name, description, schema }, handler)` helper that calls `server.tool(...)` and wraps each handler's domain-object return value once into `{ content: [{ type: "text", text: JSON.stringify(result) }] }` (preserves today's success wire format; centralizes MCP-content wrapping so handlers stay clean).
- Register all 16 tools, binding `httpClient` via closure: `register(..., (args) => handleX(httpClient, args))`.
- `await server.run({ transportType: "stdio" })`.
- Delete: `TOOL_DEFINITIONS` (~430 lines), the two `setRequestHandler` blocks, `MoneyManagerMcpServer` class, manual SIGINT/SIGTERM (FastMCP's stdio run handles lifecycle).
- Keep stderr logging.

**3. `src/tools/handlers.ts` (~850 → ~640 lines)**
- Change every handler signature from `(httpClient, input: unknown)` → `(httpClient, args: XxxInput)` using the inferred type from its schema.
- Remove the leading `const validated = XxxSchema.parse(input);` line in each handler; rename `validated.` → `args.` (already validated by FastMCP).
- Remove `handleBackupDownload`, `handleBackupRestore`.
- Remove the dispatch machinery: `toolHandlers` registry, `executeToolHandler`, `ToolHandler` type, `ToolHandlerName` (FastMCP owns dispatch now). Keep `toNumber` helper (still used by asset/card list).
- Handlers remain pure `(httpClient, args) → domain object` functions — still unit-testable with a mock client.

**4. `src/schemas/index.ts` (~438 → ~350 lines)**
- Remove `BackupDownloadInputSchema`, `BackupRestoreInputSchema` + their `*Input` types.
- Remove the `ToolSchemas` registry, `ToolName`, `validateToolInput`, `safeValidateToolInput` (no longer needed — FastMCP validates; no central dispatch).
- Keep all individual `*InputSchema` exports + `*Input` inferred types (consumed by handlers + registration).

**5. `src/types/index.ts`**
- Remove `BackupDownloadResponse`, `BackupRestoreResponse`. Everything else unchanged.

**6. `src/errors/index.ts`**
- **No code changes.** The class hierarchy (`NetworkError`, `APIError`, `ValidationError`, `SessionError`, `FileError`, `InternalError`, `wrapError`) stays as the internal error taxonomy. Handlers/http-client keep throwing these; FastMCP surfaces thrown errors natively. Note: the structured `{code, category, retryable}` metadata is flattened to the error's `.message` in the client-facing payload (acceptable per the error-format decision).

**Unchanged files:** `src/client/http-client.ts`, `src/config/index.ts`, `tsconfig.json`, `.env.example`.

**7. `README.md` + `docs/technical/ARCHITECTURE.md`**
- Note the framework is now `fastmcp`; update the "18 tools" wording stays correct (backups were already unadvertised).
- Replace the error-envelope description with a note that tool errors are returned as native MCP error results.
- Keep the VS Code / Claude Desktop install snippets (they're transport-level, unaffected: still `stdio` + `npx money-manager-mcp@latest --baseUrl <ip:port>`).

### Behavior preserved (verified edge cases)
- `transaction_delete` ID format `:id1:id2:id3` — kept in handler.
- `transfer_update` destructive-new-ID warning — kept in handler.
- `summary_export_excel` `.xlsx`→`.xls` auto-correction + warning — kept.
- `dashboard_get_asset_chart` uses **POST** `/getEachAssetChartData` — kept.
- `transaction_list` three XML empty-response branches + xml2js options — kept.
- `parseJsLiteralResponse` JS-literal→JSON + eval fallback in http-client — untouched.
- Cookie session persistence — untouched.

### Behavior changes (intentional)
- Error payload no longer wrapped in `{ success:false, error:{...} }` JSON envelope; native MCP `isError` results instead.
- `backup_download` / `backup_restore` no longer present or callable (fixes the silent-callable dispatch bug).

### Out of scope
- No new tests (none exist today; the repo has `vitest` configured but no test files). Refactored handlers are more testable as a side benefit.
- No structured-output migration for success results (kept as JSON text to preserve wire format).

### Verification
- `npm install` (new `fastmcp` dep), then `npm run build` (tsc strict must pass).
- `npm run lint`.
- Manual smoke check: launch against a Money Manager base URL and invoke `tools/list` + a read tool (`init_get_data` / `asset_list`) to confirm registration, schema advertisement, and dispatch.
